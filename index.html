The Autonomy Gap

AI agents are a black box. That’s the gap.

You hand work to agents. They hand back finished. Finished by whose measure? Without verification, you’re flying blind — and the bigger the fleet, the blinder.

THE FOUNDING PAIN
“Done” with no proof.
Agents report done when the work isn’t. Prismatic derives the verdict from the done gate — exact checks, exit codes, evidence — never from the agent’s word.
MERGE DISCIPLINE
Nobody watching the merge.
Producers shouldn’t merge their own unverified work. The verification contract forbids self-authorized merges: the reviewed SHA must equal the PR head at merge time.
APPROVALS
Risky actions, no approval.
Policy enforcement runs before risky work, not after. Production deploys and auth/security paths stay human-only — always.
AUDIT
No trail when it matters.
Durable jobs, append-only audit events, artifact provenance, a trust ledger of every merge outcome. Reconstruct anything, any time.
How it works

Produce. Verify. Receipt. Merge.

STEP 1
Produce
Any harness does the work — Claude Code CLI, Gemini CLI, Codex CLI, Hermes agents, GitHub PRs, or your own CLI behind a JSON envelope.
STEP 2
Verify
The engine checks the work independently: exact commands, exit codes, digests, measured against the verification contract. Plausible output is not verified completion.
STEP 3
Receipt
Every run gets a signed proof-of-done receipt — what was checked, what passed, what failed, and a DONE / NOT DONE verdict. Ed25519-signed, persisted, dashboard-visible.
STEP 4
Merge
Verified work merges under earned-autonomy tiers with a signed merge receipt. Unverified work waits. Novel work quarantines. Nothing merges on a claim.

Capabilities

One engine. Every harness. Full audit.

RECEIPTS
Proof-of-done receipts
Signed, persisted, readable. The verdict comes from the checks, not the chat.
NEUTRALITY
Provider-neutral verification
GitHub, GitLab, Bitbucket, Forgejo, or local. A provider outage reports BLOCKED — never PASS.
AUTONOMY
Earned autonomy
T0 is manual today. Higher tiers are earned on evidence from the trust ledger, and promotion stays a human decision.
HARNESSES
Harness agnostic
Swappable adapters. Any CLI agent that reads a JSON task envelope and prints JSON back can be driven — zero per-harness code.
GOVERNANCE
Plugin governance
Catalog, load gates, policy enforcement before risky work, durable jobs, audit events, artifact provenance.
LOCAL
Local-first
Runs on your machine. Your code, your keys, your ledger. No mandatory cloud, no lock-in.
Proof, not promises

It runs its own development.

Every change to Prismatic Engine goes through the same machinery: verified in CI, receipted, merged under the same gates. The trust ledger, the receipts, the quarantine history — all in the public repo. We don’t ask you to trust the engine. We ask you to verify it.

No lock-in

Your verification shouldn’t depend on your provider.

A GitHub outage reports BLOCKED — never PASS. Verification receipts are provider-neutral: GitHub, GitLab, Bitbucket, Forgejo, or local. No mandatory cloud, no mandatory backend.

Install

Running in five steps.

terminal bash
$ git clone https://github.com/mbgulden/prismatic-engine.git
$ cd prismatic-engine
$ python3 -m venv .venv
$ . .venv/bin/activate
$ python -m pip install --upgrade pip
$ python -m pip install -e ".[gateway]"
$ cp .env.example .env
$ python scripts/public_launch_smoke.py
# expected: PUBLIC_LAUNCH_SMOKE_OK

Linux or macOS · Python 3.10–3.13 · Developer preview — not a hosted service.
