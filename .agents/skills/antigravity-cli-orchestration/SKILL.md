## Binary layout + non-TTY launch (transport facts)

These belong at the top because every dispatch touches them.

**Binary layout (verified Jun 18 2026):**
- `~/.local/bin/agy` is a 1-line bash wrapper: `exec /home/ubuntu/.local/bin/agy-bin --dangerously-skip-permissions "$@"`
- The real CLI is `~/.local/bin/agy-bin` (~172 MB).
- Both call paths produce the same behavior. Call `agy-bin` directly when you want to bypass shell-level PATH or env quirks (e.g., when the dispatch tool is in a minimal sandbox that doesn't source `~/.local/bin`).
- The wrapper adds nothing except convenience — and the `--dangerously-skip-permissions` flag is always passed, which is what you want for headless dispatch.

**Non-TTY launch (cron, CI, automated `terminal()` calls):**
- `agy --prompt-interactive` opens a bubbletea TTY. Outside an interactive shell it dies with: `error opening TTY: bubbletea: could not open TTY: open /dev/tty: no such device or address`
- Fix pattern A — wrap with `script(1)`:
  ```bash
  script -qc "cd /tmp && agy --prompt-interactive --print 'Goal: ...' 2>&1" /dev/null | tail -200
  ```
- Fix pattern B — Hermes `terminal` tool with `pty=true`:
  ```
  terminal(command="cd /tmp && agy --prompt-interactive --print 'Goal: ...' 2>&1", pty=true, background=true, notify_on_complete=true)
  ```
- Fix pattern C — pure headless (`--print` only, no interactive niceties):
  ```bash
  cd /tmp && agy --prompt-interactive --print "Goal: ..." 2>&1 </dev/null
  ```
- For long-running headless dispatches, pair `script -qc` with `timeout` so the wrapper can't hang the parent:
  ```bash
  timeout 600 script -qc "cd /tmp && agy --prompt-interactive --print 'Goal: ...' 2>&1" /dev/null | tail -400
  ```

**Failure surface (what to do when each error shows up):**

| Error | Cause | Fix |
|---|---|---|
| `error opening TTY: ... open /dev/tty: no such device` | No TTY in the parent context | Use `script -qc` or `terminal(pty=true)` |
| `command not found: agy` | PATH missing `~/.local/bin` | `export PATH="$HOME/.local/bin:$PATH"` or call `agy-bin` with full path |
| `agy: Permission denied` | Wrapper lost exec bit | `chmod +x ~/.local/bin/agy ~/.local/bin/agy-bin` |
| Process runs but no output for >5 min, `wchar: 0` from `/proc/<pid>/io` | Can be normal under `wchan=pipe_read` while waiting on LLM stream — see profile-Home mismatch reference below | Do not kill immediately; first verify age, model, and transport |
| Non-PTY `--print` launch stays at zero-byte log / `wchar: 0` but a PTY smoke test (`AGY_SMOKE_OK`) succeeds | Transport starvation in non-PTY background mode, not AGY intelligence/auth failure. Verified Jun 18 2026 on `agent:agy-pro` and `agent:agy` relaunches. | Relaunch with Hermes `terminal(..., pty=true, background=true, notify_on_complete=true)` or `script -qc`; prefer normal `agent:agy` / `gemini-3.5-flash-high` before retrying `agent:agy-pro`. |

## Scheduled watchdog cron reporting quick path

When a cron prompt asks for the AGY watchdog (`agy_watchdog.py`), treat the run as a snapshot/reporting task, not an interactive repair session:

1. Run the watchdog with a bounded invocation (prefer `timeout 10 python3 /home/ubuntu/work/agentic-swarm-ops/ops/agy_watchdog.py`) so the loop cannot hang the report.
2. If `$PRISMATIC_HOME/work/...` expands to a missing `/work/work/...` path, recover immediately with the canonical `/home/ubuntu/work/agentic-swarm-ops/ops/agy_watchdog.py` path and mention it as an ops footnote rather than failing the report.
3. Interpret `OAuth: valid (...)` from the token file as authoritative over AGY internal `error getting token source` / `Singleflight refresh failed` log lines.
   - OAuth verification pitfall: do **not** run broad recursive token discovery under `/home/ubuntu` during watchdog cron triage (`find /home/ubuntu ...` / recursive glob / ripgrep file search). It can hang on prior orphan `find` processes or deep profile trees and burn the cron window. Check scoped token locations instead: `/home/ubuntu/.gemini/antigravity-cli/antigravity-oauth-token`, `/home/ubuntu/.hermes/profiles/orchestrator/home/.gemini/antigravity-cli/antigravity-oauth-token`, and the active profile home if known (e.g. `/home/ubuntu/.hermes/profiles/ned/home/.gemini/...`).
4. Count only `[a]gy-bin` processes as AGY processes. Separately note orphan classes (`find ... antigravity-oauth-token`, brain scratch workers, `$HOME` scratch `.py`) as hygiene findings, but do **not** include them in the AGY process count.
   - Verification pitfall: after running watchdog commands that contain the string `agy-bin`, `pgrep -f '[a]gy-bin'` can match the current shell/tool wrapper rather than a real AGY process. For final counts, verify with an exact process-name check such as `ps -C agy-bin` or `/proc/*/comm == 'agy-bin'` before reporting active/stuck AGY processes.
   - If a PID flagged by the watchdog disappears before verification and a result file/log completion exists, report it as completed/transient rather than active-stuck.
5. On CPU-only hosts (`nvidia-smi` and `ollama` missing), treat the repeated GPU failover line as informational unless config verification shows failover did not actually route away from local Ollama endpoints. **Mandatory:** whenever the watchdog prints `Local GPU instances are unresponsive! Triggering automatic OpenRouter failover`, run the verification grep from `references/agy-watchdog-ops-bugs-20260616.md` Bug 6 — `update_profile_configs()` is a silent no-op when the orchestrator config uses bare provider names instead of `custom:ollama-*` (confirmed Jun 18 2026 04:42 UTC AND 09:29 UTC). Report "failover intent" not "failover applied" unless the grep confirms OpenRouter is now the active default.
