# GRO-3570 — Jules Host-Path Pre-screening & Auto-routing

## Operator contract

Jules runs in a repository-only sandbox. The dispatcher must not launch Jules for Linear issues whose title or description requires host-level access such as `/home/ubuntu`, `/etc`, host crontabs, `~/.config`, `~/.hermes`, or systemd.

## Implemented behavior

- `prismatic.dispatcher.detect_host_level_patterns(issue)` scans issue title and description for host-path/scheduler markers.
- During `dispatch_once`, the `agent:jules` loop runs the host-path pre-screen before transition approval, credit-policy evaluation, or process launch.
- If a host marker is found, `reroute_jules_host_path_issue(...)`:
  - removes `agent:jules` / `agent::jules` from the issue labels,
  - adds `agent:ned-infra` by default, falling back to `agent:agy` if needed,
  - posts a Linear comment explaining the sandbox mismatch and detected markers,
  - marks the item processed for the current cycle, and
  - skips the Jules launcher.

## Verification

python3 -m pytest prismatic/tests/test_jules_host_path_routing.py -q

The test covers marker detection, label/comment mutation shape, and the `dispatch_once` no-launch path for a Jules issue containing `/home/ubuntu` + `crontab` host requirements.
